# Calories Coach

Offline-first calories and macros tracker built with React + Vite.

The app is installable as a PWA, stores data locally in IndexedDB, supports meal templates, exercise tracking, data export/restore, and optional AI-based nutrition estimation from food photos.

## Features

- Daily calories + macros tracking (protein/carbs/fat)
- Custom foods and reusable meals
- Exercise tracking and calorie-burn integration
- Dashboard with daily balance and short history trend
- Offline-first behavior via service worker caching
- Installable PWA (home screen app on Android/iOS)
- Backup/restore all local data as JSON
- Optional AI nutrition estimate from photo (OpenAI or Gemini)

## Tech Stack

- React 19
- Vite 8
- Dexie (IndexedDB wrapper)
- Tailwind CSS
- react-icons

## PWA and Update Sync Behavior

This project is configured so installed apps can update quickly after each deploy:

- Service worker is registered from `src/main.jsx`.
- App requests updates on load (`registration.update()`) and every hour.
- When a new worker is installed, it receives `SKIP_WAITING` and activates immediately.
- On `controllerchange`, the app shows an update toast and reloads.
- Navigation requests in `public/service-worker.js` are network-first.

### Required server cache headers

For reliable updates on installed devices, configure hosting/CDN headers as follows:

- `service-worker.js`: `Cache-Control: no-cache, no-store, must-revalidate`
- `index.html`: `Cache-Control: no-cache`
- `/assets/*` (hashed files): `Cache-Control: public, max-age=31536000, immutable`
- `manifest.json`: `Cache-Control: no-cache` (recommended)

Without these headers, some devices may keep stale files longer than expected.

## Data Model and Storage

All user data is local-first in IndexedDB (`CaloriesCoachDB`):

- `foods`
- `meals`
- `logs`
- `exercises`
- `settings`
- `meta`

Base foods are seeded from `public/foods.json` (tracked via `seedVersion` in `meta`).

## Backup and Restore

The app can export and restore all local data as JSON.

- Export returns payload with metadata (`exportedAt`, `app`, `version`, `data`).
- Restore clears current local tables, then imports from backup.

Use this before switching devices or before major testing sessions.

## AI Nutrition Estimation (Optional)

AI image estimation is optional and uses direct API calls from the client:

- OpenAI Chat Completions endpoint
- Google Gemini generateContent endpoint

You must provide your own API key in app settings.

Important:

- API keys are stored locally in app settings (client-side).
- Do not use production organization keys in untrusted environments.
- For stronger security, proxy requests through your own backend.

## Deployment

The app is built as a static site.

General deployment flow:

1. `npm run build`
2. Upload contents of `calories/` to your host
3. Ensure cache headers match the PWA section above
4. Verify update flow by opening an installed app after a deploy

### Base path behavior

`vite.config.js` uses `base: './'`, so assets are referenced relatively. This is useful for subpath/static hosting scenarios.

## Troubleshooting

### Installed app does not update

- Confirm `service-worker.js` is not cached by CDN
- Confirm `index.html` is no-cache
- Open the app while online to let update checks run
- Test once with browser storage/site data cleared

### Foods list did not refresh after editing foods.json

- Increase `SEED_VERSION` in `src/db.js`
- Rebuild and redeploy
